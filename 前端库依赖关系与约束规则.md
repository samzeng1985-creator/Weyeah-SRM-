### 1.3 调用层级关系

```
层级 1: 基础工具层 (无依赖)
────────────────────────────────────
log        - 日志工具
db         - 数据存储
env-config - 环境配置

层级 2: 中间服务层 (依赖层级1)
────────────────────────────────────
mock       - Mock数据服务 (依赖 env-config)
request    - 网络请求 (依赖 env-config)

层级 3: 功能应用层 (依赖层级1、2)
────────────────────────────────────
components - 业务组件 (依赖 log, request, env-config)
pdf        - PDF处理 (依赖 request, env-config)

层级 4: 接口层 (依赖层级2、3)
────────────────────────────────────
api/*      - API接口 (依赖 request 或 mock)
           - 在开发环境可切换使用 mock
           - 生产环境使用 request

页面层使用示例:
────────────────────────────────────
import { request } from '@/libs'      // 层级2
import { createLogger } from '@/libs' // 层级1
import api from '@/api/supplier'      // 层级4

const logger = createLogger('SupplierPage')
logger.info('页面加载')

const data = await api.getSupplierList(params) // request
```

## 2. 核心约束规则

### 2.1 依赖方向约束（单向依赖）

```
✅ 正确：下层依赖上层（单向）
────────────────────────────────────
libs/index.ts      (导出层)
    ▲
    │
libs/log ← pages/ (使用层)

❌ 错误：循环依赖
────────────────────────────────────
libs/log → libs/request → libs/mock → libs/log ❌ 循环!

❌ 错误：上层依赖下层
────────────────────────────────────
libs/log           (层级1)
    ▲
    │
libs/components   (层级2) ❌ 不应该依赖更底层的log!
```

### 2.2 libs 库独立性约束

```
┌─────────────────────────────────────────────────────────────────────┐
│                           libs/ 内部约束                             │
│                                                                       │
│  核心原则：libs 内部的各库之间，禁止横向直接依赖                     │
│                                                                       │
│  ✅ 允许的依赖：                                                      │
│  ┌───────────────────────────────────────────────────────────────┐   │
│  │  libs/*   →   env-config                                     │   │
│  │  (所有库)      (环境配置，被所有库依赖)                        │   │
│  └───────────────────────────────────────────────────────────────┘   │
│                                                                       │
│  ✅ 允许的依赖：                                                      │
│  ┌───────────────────────────────────────────────────────────────┐   │
│  │  libs/request   →   libs/log                                 │   │
│  │  (网络请求)        (日志，记录请求日志)                        │   │
│  └───────────────────────────────────────────────────────────────┘   │
│                                                                       │
│  ❌ 禁止的依赖：                                                      │
│  ┌───────────────────────────────────────────────────────────────┐   │
│  │  libs/mock   →   libs/request                                │   │
│  │  libs/mock   →   libs/components                              │   │
│  │  libs/log    →   libs/mock                                    │   │
│  │  (禁止横向依赖)                                                │   │
│  └───────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 API 层约束

```
API 层使用规则
═══════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────┐
│  api/xxx.ts                                                        │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │                                                                 │   │
│  │  // 开发环境优先使用 Mock                                       │   │
│  │  if (isDev && ENABLE_MOCK) {                                │   │
│  │      return mockXxx()                                          │   │
│  │  }                                                             │   │
│  │                                                                 │   │
│  │  // 生产环境使用真实请求                                         │   │
│  │  return request.get('/xxx')                                   │   │
│  │                                                                 │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘

约束规则:
────────────────────────────────────
✅ api/ 可依赖 libs/request
✅ api/ 可依赖 libs/mock
✅ api/ 可依赖 libs/log
❌ api/ 禁止依赖 libs/components (业务组件)
❌ api/ 禁止依赖 libs/pdf (功能组件)
```

### 2.4 页面层约束

```
页面使用规则
═══════════════════════════════════════════════════════════════════════

页面使用优先级:
────────────────────────────────────
1. libs/components (推荐优先使用)
   - 封装好的业务组件
   - 开箱即用
   - 统一交互体验

2. libs/* 工具库 (按需使用)
   - request: API调用
   - log: 日志记录
   - env-config: 环境判断
   - pdf: PDF操作

3. Element Plus 原生组件 (基础UI)
   - 必须在 components/ 封装后使用
   - 保持组件风格统一

页面代码示例:
────────────────────────────────────
✅ 推荐写法:
────────────────────────────────────
<template>
  <!-- 使用封装好的业务组件 -->
  <SupplierTable 
    :data="list"
    @selection-change="handleSelect"
  />
  
  <!-- 使用封装的请求 -->
  <el-button @click="handleSubmit">
    提交
  </el-button>
</template>

<script setup>
import { SupplierTable } from '@/libs/components'
import { createLogger } from '@/libs'
import api from '@/api/supplier'

const logger = createLogger('SupplierList')
const list = ref([])

const loadData = async () => {
  logger.info('加载数据')
  list.value = await api.getSupplierList()
}
</script>

❌ 不推荐写法:
────────────────────────────────────
// 禁止在页面中直接使用 Element Plus 基础组件
// 应该封装到 libs/components 中

// ❌ 错误
<template>
  <el-table :data="list">
    <el-table-column prop="name" label="名称" />
  </el-table>
</template>

// ✅ 正确
<template>
  <SupplierTable :data="list" />
</template>
```

## 4. 环境切换约束

### 4.1 开发/生产切换规则

```
环境切换约束
═══════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────┐
│                         env-config                                  │
│                                                                       │
│  配置文件位置: src/libs/env-config/index.ts                         │
│                                                                       │
│  切换方式:                                                           │
│  1. Vite 配置: import.meta.env.MODE                                 │
│  2. 运行时切换: switchEnv('production')                              │
│                                                                       │
│  ⚠️ 约束:                                                           │
│  - 禁止在业务代码中硬编码环境判断                                     │
│  - 必须使用 env-config 提供的常量                                     │
└─────────────────────────────────────────────────────────────────────┘

❌ 禁止的写法:
────────────────────────────────────
// 硬编码判断
if (process.env.NODE_ENV === 'development') { ... }

// 硬编码 URL
const baseURL = 'http://localhost:8080'

✅ 正确的写法:
────────────────────────────────────
// 使用 env-config
import { envConfig, isDev } from '@/libs/env-config'

if (isDev) {
  // 开发环境逻辑
}

// 使用配置的 URL
const baseURL = envConfig.API_BASE_URL
```

### 4.2 Mock 切换约束

```
Mock 使用规则
═══════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────┐
│  Mock 启用条件                                                       │
│                                                                       │
│  ✅ 启用 Mock 的条件 (同时满足):                                       │
│  - isDev === true (开发环境)                                        │
│  - ENABLE_MOCK === true (配置开启)                                   │
│  - 后端接口未就绪 (API 还在开发中)                                    │
│                                                                       │
│  ❌ 禁止在生产环境启用 Mock                                            │
└─────────────────────────────────────────────────────────────────────┘

Mock 切换代码示例:
────────────────────────────────────

// api/supplier.ts
import { envConfig, isDev } from '@/libs/env-config'
import { mockGetSupplierList } from '@/libs/mock/supplier'
import request from '@/libs/request'

export const getSupplierList = async (params: any) => {
  // 开发环境 + 启用 Mock + 接口未就绪
  if (isDev && envConfig.ENABLE_MOCK && !import.meta.env.VITE_API_READY) {
    return mockGetSupplierList(params)
  }
  
  // 生产环境 或 Mock 未启用
  return request.get('/supplier/list', params)
}

⚠️ 约束:
────────────────────────────────────
- Mock 数据必须与真实接口返回格式一致
- Mock 切换必须对调用方透明
- 生产构建时必须移除所有 Mock 代码
```

```
│  api/* → libs/log      ✅      API 层使用日志                        │
│  api/* → libs/components ❌     禁止 API 层依赖组件                  │
├─────────────────────────────────────────────────────────────────────┤
│  libs/log → libs/*    ❌      禁止横向依赖                          │
│  libs/mock → libs/*    ❌      禁止横向依赖                          │
│  libs/request → libs/* ❌      禁止横向依赖                          │
│  libs/* → env-config   ✅      所有库可依赖环境配置                 │
├─────────────────────────────────────────────────────────────────────┤
│  components → libs/*   ✅      组件可使用所有 libs                   │
│  components → pages/*  ❌      禁止依赖页面层                       │
│  components → api/*    ✅      组件可使用 API 层                    │
├─────────────────────────────────────────────────────────────────────┤
│  ❌ 禁止循环依赖                                                     │
│  ❌ 禁止反向依赖 (下层依赖上层)                                       │
│  ❌ 禁止跨层依赖 (如 libs 依赖 pages)                               │
└─────────────────────────────────────────────────────────────────────┘
```

## 7. 违规检测与修复

### 7.1 检测工具

```bash
# 检查循环依赖
npm run depcheck

# 检查未使用的依赖
npm run lint:unused

# TypeScript 类型检查
npm run typecheck

# ESLint 检查
npm run lint
```

### 7.2 常见违规修复

```
违规场景1: 循环依赖
────────────────────────────────────

A.ts → B.ts → A.ts

修复:
- 将公共部分提取到 C.ts
- A 和 B 都依赖 C
- A 和 B 不直接相互依赖

违规场景2: 跨层依赖
────────────────────────────────────

libs/mock → api/xxx

修复:
- 将 mock 独立，不依赖 api
- 或将公共逻辑提取到 libs/common/
```
