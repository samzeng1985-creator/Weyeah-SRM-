## 二、飞书集成需求分析

### 2.1 PRD中的飞书描述（第7.6节）

#### 功能范围
1. **审批流程集成**
   - 使用飞书审批作为企业统一审批入口
   - 通过飞书审批开放平台API深度集成
   - 支持审批流程的回调通知和状态同步

2. **通知推送**
   - 审批待办通知（飞书机器人/消息卡片）
   - 审批结果通知（通过/驳回）
   - 审批超时提醒
   - 涨价预警通知

3. **人员同步**
   - 从飞书同步组织架构和人员信息
   - 审批人自动获取

#### 配置项
| 配置项 | 说明 |
|--------|------|
| 飞书应用App ID | 飞书开放平台应用ID |
| 飞书应用App Secret | 飞书开放平台应用密钥 |
| 审批流程映射 | 配置本系统业务与飞书审批模板的对应关系 |
| 通知模板 | 配置飞书消息卡片的样式和内容 |
| Webhook地址 | 飞书接收本系统回调的地址 |

#### 技术实现
- 飞书开放平台API
  - 飞书审批套件API
  - 飞书消息订阅API
  - 飞书通讯录API

- 数据流向
```
本系统 → 飞书多维表格/审批 → 审批结果回调 → 本系统更新状态
```

### 2.2 注意事项
1. 审批流程统一：建议优先使用飞书进行审批，本系统仅作为数据记录和业务处理层
2. 数据一致性：审批完成后需确保本系统数据与飞书审批结果一致

## 三、企业微信集成需求分析

### 3.1 PRD中的企业微信描述

#### 仅提及场景：图纸安全访问
- 供应商通过企业微信端查看图纸时，系统自动在PDF预览画面叠加动态水印
- 供应商业务员需绑定企业微信账号才能访问
- 访问权限与合同状态关联（合同终止后自动收回权限）

### 3.2 企业微信供应商协同集成（第7.8节）

#### 功能概述
- 代加工供应商通过企业微信接收生产需求订单
- 供应商可在企业微信中查看订单详情、技术要求、图纸信息
- 支持订单确认、进度反馈、发货通知等协同操作
- 减少采购人员与供应商的反复沟通

#### 核心场景：委托加工订单下推
```
采购人员创建委托加工订单 → 系统自动推送至企业微信 → 供应商接收并确认 → 供应商反馈生产进度 → 系统通知采购人员
```

#### 支持的供应商操作

| 操作 | 说明 |
|------|------|
| 接收订单 | 自动接收新的委托加工订单 |
| 查看详情 | 查看物料信息、技术要求、图纸、交期等 |
| 确认订单 | 确认订单内容和交期 |
| 更新进度 | 更新生产进度（备料中/生产中/质检中/待发货） |
| 发货通知 | 提交发货信息和物流单号 |
| 问题反馈 | 对订单有疑问时进行反馈 |

#### 消息推送内容示例

**订单推送消息卡片**

## 四、统一身份账号中心（UAC）（第7.7节）

### 4.1 设计背景
为实现SRM系统与企业微信（WeCom）间的供应商身份统一管理，解决供应商业务员人员流动导致的账号切换问题，系统建立统一身份账号中心（Unified Account Center）。

### 4.2 核心功能
- 供应商业务员企业微信账号绑定
- 多账号映射管理
- 人员流动自动处理

### 4.3 映射表设计

| 字段 | 类型 | 说明 |
|------|------|------|
| mapping_id | UUID | 主键 |
| supplier_id | 供应商ID | SRM系统供应商标识 |
| uac_user_id | 字符串 | UAC用户唯一标识 |
| wecom_user_id | 字符串 | 企业微信用户ID |
| is_primary | 布尔 | 是否为主账号 |
| status | 枚举 | 正常/禁用 |
| created_at | 时间戳 | 创建时间 |
| updated_at | 时间戳 | 更新时间 |

### 4.4 典型场景

**场景1：供应商业务员新增**
```
1. 供应商管理员在企业微信中添加新业务员
2. 新业务员通过企业微信扫码绑定SRM系统
3. 系统自动创建映射记录（is_primary=false）
4. 新业务员获得基础权限（查看订单、接收通知）
```

**场景2：供应商业务员离职**
```
1. 供应商管理员在企业微信中禁用/删除离职人员
2. 同步触发SRM映射记录更新（status=禁用）
3. 如果离职人员为主账号，自动转移给其他有效账号
4. 离职人员的业务数据保留（关联到Supplier_ID）
```
